# Work: sprints and estimates

Reference detail moved word for word from `wikantik-work/CLAUDE.md`. The invariants are in that file; where a class Javadoc states a rule, the Javadoc is the authority. Read this before changing the area.

Small teams, part 2. Plan: `docs/superpowers/plans/2026-11-21-work-team-02-sprints-and-estimates.md` (its "Decisions" P2-1 onward say what was settled).

- **Schema and doors.** V085: `work_sprint`, `work_item.sprint_id`, `work_item.estimate`. Reached as `WorkService.features().sprints()` (`WorkSprintsService`) and `store.sprints()` (`JdbcWorkSprints`; transitions in `JdbcSprintTransitions`, history reads in `JdbcSprintHistory`). `WorkService`, `JdbcWorkStore` and `WorkPolicy.may` are at their PMD limits: new facades go on `WorkFeatures`, new SQL in a new `Jdbc*` class, agent refusals in `WorkPolicy.agentRefusal`.
- **Who may do what.** `MANAGE_SPRINT` (create, edit, start, close) is a lead's; `PLAN_SPRINT` (setting an item's `sprint`, gated in `ItemGates.requireFieldGates`) is a member's. An agent is refused both with "A person plans a sprint." Estimating is `EDIT_ITEM`, so an agent may estimate. Stories and tasks only: an epic is never in a sprint and has no estimate (its points come from `GET items/{key}/points`).
- **One active sprint** per project (`idx_work_sprint_active`; the conflict is `sprint_active`). A closed sprint takes no items and does not change; an item may leave it (`sprint_closed`). Starting and closing write the four figures on the sprint row (committed and completed, items and points): they are the record of the promise and are never recomputed.
- **Lock order: sprint rows, then item rows.** An item write takes `FOR SHARE` on its sprint rows first (`lockSprints` in `JdbcWorkItemWrites`); `start` and `close` lock the sprint rows, then the items. Keep it.
- **The close event precedes its moves, and the report cuts at event ids, never times** ("before the start" and "before the close" are decided by event id), so the close's own moves do not empty the last day.
- **`Burndown` is pure** and replays `field` (`sprint`, `estimate`) events and every status move as `StatusMoves` defines it (`JdbcSprintHistory` selects with `StatusMoves.movedSql`). Claims never move an item into or out of done or cancelled, so including them changes no figure; a new way to reach `done` must be added to `StatusMoves`. Days and weeks use the work clock's zone; `WorkWiring` passing `Clock.systemDefaultZone()` is the one place a zone is chosen.
- **No query assumes sprints exist.** The board's default to the active sprint is client-side only (the `sprint=` filter is `active|none|<id>`, parsed in `WorkFilters`). Claimable work lists active-sprint items first. Sprint events: `sprint_created`, `sprint_updated`, `sprint_started`, `sprint_closed`; their text is in `eventText.js`.
