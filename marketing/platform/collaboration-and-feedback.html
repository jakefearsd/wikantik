Collaborative editing, reader comments and a feedback loop for agents

Several people can edit one page in a shared draft and publish it as a single credited version. Readers can comment on any passage. Agents that publish pages can read those comments and answer them, under a trust rule that keeps unverified text from closing a thread.

Edit together in a shared draft

With collaborative editing turned on, choosing Edit on a page joins that page's shared draft. Nobody invites anyone or starts a session. Everyone editing types into the same text, and a status bar shows Live, Reconnecting or Resync needed. It is controlled by wikantik.collab.enabled, which defaults to off; the live Wikantik instance has run with it on since 2026-11-07. When it is off the editor works as it always has: you edit alone and Save writes a new version.

Presence

The other editors' names appear in the bar, each with a colour, and their cursors and selections show in the text in that colour. Frontmatter is shared too. Two people can add different tags at once and both are kept; for a single-value field such as the summary, the later change wins and the form shows who changed it.

The draft outlives the editor

Your edits go to the draft as you type, not to the page. When you close the editor, unpublished changes stay in the draft until someone publishes or discards them, and a banner on the page says so: "Unpublished changes by Ana and Raj — last edit 2h ago". Operators can set wikantik.collab.draft.retentionDays to delete drafts nobody has touched for that many days (default 0, keep forever; production uses 30). A draft is never published automatically.

Outside writers merge in

A page can change while you edit it: an agent saves it through MCP or REST, someone renames a cluster, a link is rewritten. Those changes merge into the live draft as they happen, with a notice of who made them. You get no conflict and lose no edits. If the page is renamed, the editor follows it to the new name. If it is deleted, the editor goes read-only and anyone allowed to create pages can recreate it from the draft.

Publishing and attribution

Any editor can Publish. The dialog shows what changed in the text since the last published version, which frontmatter fields changed, who contributed, and a change note box. Publishing writes one new page version for everyone. The page history then credits the publisher and the other contributors, for example "v8 — Ana +2", and lists the other contributors by name in the change note. Discard resets the draft to the published page for everyone in it, after a confirmation that says how many people are editing.

Operators get audit-log entries for joins, publishes, discards, purges and evictions, wikantik_collab_* metrics, and an admin list of stored drafts (GET /admin/collab/drafts) with an audited removal (DELETE /admin/collab/drafts/{id}). The editor itself is described on the Rich editor page.

Reader comment threads

Readers select a passage on a rendered page and comment on it, Google-Docs style. Each thread is anchored to that passage, holds replies, and can be open or resolved. Threads are keyed to the page's canonical id, so they survive a rename; a thread whose anchor text has been edited away is grouped as Detached. A Comments (N) button opens a drawer with Open, Resolved and All filters.

  • Permissions. Anyone with the page comment permission can post, reply, resolve and reopen. Deleting a thread needs the page delete permission. Anonymous visitors cannot comment.
  • Mentions. Typing @ in a comment offers matching people by display name. A mention notifies the person in a per-user inbox at /me/mentions, with an unread badge. The first comment on a page also notifies the page owner. Mentions work in comment boxes, not in the page editor.

The agent comment feedback loop

Publishing agents write pages. Readers react to them. The loop closes when the agent can read that reaction and answer it, with rules on what it may do. It uses two admin-MCP tools on /wikantik-admin-mcp (see MCP for AI agents):

  • list_comment_threads returns the threads readers made available to agents, by page or cluster. Each comment is marked trusted or not, and comment bodies reach the agent as data.
  • respond_to_comment_thread replies, resolves or dismisses, always with a written body. Dismissing needs a reason. A thread closes once: the first agent to resolve or dismiss wins and a second is refused. The commenter is told through the mentions feed.

Readers stay in control. The new-comment form carries an Agents may respond to this comment checkbox, ticked by default, and only threads where it was left on appear to agents.

The trust rule. A comment is trusted only when its author was signed in and could edit the page when posting. An agent may resolve a thread only when it holds a trusted human comment. Otherwise it can reply or dismiss, but not mark the feedback as handled.

  • Dismissed is a third thread status beside open and resolved. The reason stays visible as the agent's closing comment, and the thread can be reopened.
  • Agent comments are badged with an "agent" label. They are stored under agent:<client name>, so a client cannot post under a member's name.
  • Existing threads become available to agents, but none carries a trusted comment until an editor replies.

Display names as public identity

People are shown to each other by display name, not login name. That matters when logins are email addresses, as with Google sign-in. Display names are unique, ignoring case, and checked against naming rules. The login shows only to its owner and to admin surfaces. Page history, comments, mentions and search author fields all show the current display name; mentions are stored by opaque user id, so they keep pointing at the right person after a rename. A deleted account shows as "former member", and its login cannot be registered again.

Frequently asked questions

Is collaborative editing on by default?

No. It is controlled by wikantik.collab.enabled, which defaults to off. When it is off the editor works as a single-author editor with a Save button. The live Wikantik instance runs with it on.

What happens to unpublished changes when I close the editor?

They stay in the page's shared draft until someone publishes or discards them. A banner on the page shows who has unpublished changes and when they last edited. An operator can set a retention period to delete untouched drafts; a draft is never published automatically.

Can an AI agent answer reader comments?

Yes, through two admin MCP tools: list_comment_threads and respond_to_comment_thread. Readers can opt a comment out with a checkbox. An agent may resolve a thread only if it holds a trusted comment from a signed-in editor; otherwise it can reply or dismiss with a written reason.

Can an agent impersonate a team member in comments?

No. Agent comments are stored under agent:<client name> and show an agent badge, so a client cannot post under a member's name.

Are login names visible to other users?

No. Public surfaces show the display name. A login is visible only to its owner and on admin surfaces.
