Platform

A Markdown wiki editor with Rich and Source modes, diagrams and Obsidian syntax

Wikantik edits plain Markdown in two modes: Rich, which reads like the finished page, and Source, which shows the text. Underneath is one file. Around it are grid tables, paste from Google Docs and Word, Obsidian syntax and vault import, sandboxed Mermaid and PlantUML diagrams, and math.

Two modes, one Markdown file

The editor has two modes. Rich shows the page much as it will read and lets you build it from the toolbar without typing Markdown. Source shows the Markdown itself. The page text is plain Markdown in both, and switching modes never changes it. Opening a page in Rich and saving it changes nothing.

  • Switch with the Rich / Source control at the end of the toolbar, or with Mod+E (Ctrl on Windows and Linux, Cmd on a Mac).
  • Rich is the default for new users. The choice is a per-user preference saved to the account (Preferences, Editor, Default editing mode).
  • In Rich, heading, list, task, quote and fence markers stay hidden, even on the line you are typing. Bold, italic and the other inline marks show on the cursor's line and hide again when it leaves. A diagram or math block is drawn until the cursor enters it, then you see its source.
  • A page still written in legacy wiki syntax opens in Source only, with a Convert to Markdown button.

Tables as a grid

In Rich mode a Markdown table is a grid you edit cell by cell. Tab and Shift+Tab move between cells, Enter moves down, and + row, + col and a menu add, move, align and delete rows and columns (Alt+T reaches them from the keyboard). Each cell edit rewrites only that cell. That matters when two people edit different cells of one table in a shared draft: both edits survive.

Tables the grid cannot represent safely, such as rows with different cell counts or a table inside a list, stay editable as Markdown rows. For several cells at once, switch to Source.

Link, embed and image cards

Click a link, a page embed or an image in Rich mode and a small card opens with its details: the page, heading and text of a wiki link, the address and text of a web link, the source and alt text of an image. Change a field and press Enter to apply it; Escape changes nothing. Mod+K opens the same card, and nothing is written to the page until you confirm it. Typing [[ completes page names, and [[Page# completes that page's headings.

Toolbar, menus and the slash command

Toolbar buttons, the / menu and the command palette all run commands from one registry, so they stay consistent. Buttons light up for the formatting at the cursor.

  • A Heading menu (Heading 1 to 4, or Paragraph).
  • An Insert menu: code block, Mermaid and PlantUML diagrams, math block, callouts, image, page embed, footnote, highlight, comment, horizontal rule and access rule.
  • Numbered list, task list, quote and strikethrough, plus language and callout-type lists on code blocks and callouts, reachable from the keyboard.

A preview that stays level with you

The rendered preview sits beside the editor and re-parses as you type. It stays level block by block: a heading, paragraph, formula, picture or table sits at the same height in both panes, and scrolling either pane scrolls the other. The preview lightly marks the block the cursor is in. A Preview button hides or shows the pane, and the browser remembers the choice. In Rich mode the pane can instead show a read-only Markdown source view that follows the cursor, so you can watch the Markdown your clicks produce.

Paste as Markdown, including images

Text copied from Google Docs, Word, Confluence, GitHub, a web page or another wiki page arrives as Markdown: headings, emphasis, links, nested and task lists, tables, quotes, code blocks (with their language when the source names one) and images. One undo removes the whole paste.

  • Images that arrive embedded in the clipboard as data: URIs upload as page attachments, named pasted-image-… and linked where they appeared. A paste brings in at most 20 images, each at most 25 MiB decoded, and the whole paste at most 64 MiB. SVG, blob:, file: and cid: images are dropped, and a message says how many.
  • Mod+Shift+V pastes plain text with no conversion. Pastes inside code are never converted, and neither are pastes on legacy-syntax pages.
  • Paste a URL over selected text to make it a link.

The Obsidian dialect

Teams that keep notes in Obsidian can write the way they already do. The reader, the editor preview and the server agree on this syntax, because tags and comments are read from the same parse the page renders from.

  • Block references. End a paragraph or list item with ^id. [[Page#^id]] links to that block and ![[Page#^id]] embeds just that block. A gutter button on each block copies the link and adds an id if the block has none and you can edit the page. Block markers are stripped from excerpts, search, chunk text, embeddings, ?format=md|json and the agent projection, and kept in page source.
  • Highlights. ==text== renders as a highlight (Mod+Shift+H toggles it on a selection).
  • Comments. %%text%% is hidden from everyone who cannot edit the page, on every surface: the rendered page, search, excerpts and agent projections. A link inside a comment is not a Page Graph edge, and a cite:// inside one is not a citation. Comments are hidden, not private: people with edit rights see them in the source and in history, and an access rule inside a comment is still enforced and locks the page.
  • Inline tags. A #tag in prose counts as a tag for the tag dictionary and page filters, and renders as a link to the tag search. SEO keywords, feeds, the sitemap and JSON-LD stay frontmatter-only.

Vault import and export

Import a zipped vault from the sidebar. It is a dry run first: you review a per-page plan with warnings, and the apply step refuses if the vault or the wiki changed since you reviewed it. Folders can become clusters, a folder note becomes the cluster hub, and existing pages are never overwritten. Links, embeds, block ids, comments, aliases and tags carry over, and referenced attachments are imported. Size limits are configurable and a refusal names the setting.

Export a selection (clusters, tags, type, status, optionally pages linked 0 to 2 hops away) as a vault zip with wikilinks, embeds, attachments, a manifest and a README. Only pages the exporter can view are included. Scripts can drive both directions over REST. Import and export need the createPages and export permissions respectively.

Diagrams: Mermaid and PlantUML

A ```mermaid or ```plantuml fence draws as a diagram in the reader, in server-rendered pages, in embeds and in both editor previews. Add the word example after the language to keep a fence as code. The diagram source stays in the page, in ?format=md and in the agent view, with a Show source toggle. A click Node "/wiki/Page" in Mermaid, or a [[/wiki/Page]] link in PlantUML, makes a real page reference that counts in backlinks and the Page Graph.

  • Mermaid is drawn in the browser at antiscript security level, with forms and inline styles stripped from labels.
  • PlantUML is drawn on the server in PlantUML's SANDBOX profile with Graphviz unreachable (Smetana layout only): no file, URL or environment access, and !include limited to the bundled C4 library. It handles class, object, component, deployment, sequence, activity, state, use case, timing, C4 and ArchiMate diagrams, plus @startsalt wireframes and @startnwdiag network diagrams, in light and dark variants.

Fail-closed validation. Both kinds are checked on the server and in the browser against one shared fixture. Mermaid %%{…}%% directives, front matter, javascript: links and click callbacks are refused. The unsafe source is shown as source with the reason. PlantUML output SVG is scrubbed to an allow-list and spliced in after the HTML sanitizer, so render caches hold only signed placeholders. Each diagram has a timeout, a bounded pool and per-page limits, and a kill switch (wikantik.fences.plantuml.enabled) turns server drawing off.

Two command-line checkers, bin/check-plantuml.sh and check-mermaid.mjs, validate every diagram in a file or folder, which is useful before a bulk content push.

Math

LaTeX math renders with KaTeX. Inline math is $E = mc^2$ (no spaces just inside the dollars), and display math is a $$ pair on their own lines. Math is checked when you save: glued or unterminated display blocks block the save with a Jump-to-error panel, while likely currency dollars and empty blocks are warnings. Write \$5 for a dollar amount. Math copied from a KaTeX-rendered page pastes back as $…$.

Frequently asked questions

What is the difference between Rich and Source mode?

Rich shows the page much as it will read and is built from the toolbar. Source shows the Markdown. Both edit the same plain Markdown text, so switching modes never changes the page. Press Mod+E to switch.

Can I paste from Google Docs or Word?

Yes. Rich clipboard content from Google Docs, Word, Confluence, GitHub and web pages converts to Markdown, and images embedded in the clipboard upload as attachments (up to 20 per paste). Mod+Shift+V pastes plain text instead.

Are diagrams safe to render from user-written text?

Both renderers fail closed. Mermaid runs at the antiscript security level and refuses directives, javascript: links and click callbacks. PlantUML draws on the server in its SANDBOX profile with no Graphviz, file, URL or environment access, and its SVG output is scrubbed to an allow-list. Refused diagrams are shown as source with the reason.

Are %%comments%% private?

They are hidden from anyone who cannot edit the page, on every surface including search and agent projections, but they are not private from editors: people with edit rights see them in source and history. An access rule inside a comment is still enforced.

Can I bring an Obsidian vault in and take pages back out?

Yes. Import is a reviewed dry run that never overwrites existing pages; export builds a vault zip from the clusters, tags or types you choose, limited to pages you can view. Both are also available over REST for scripts.
